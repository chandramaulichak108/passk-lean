# Pass@k learning: Lean 4 formalization (work in progress)

Lean 4/Mathlib companion to the attached LaTeX manuscript `arxiv_main_v2.tex`.

> **Not a complete formalization of the paper.** This project formalizes finite-space definitions and several genuine lemmas, but the full online-regret, exponential-moment, high-probability and minimax theorems are **not yet machine verified**. In particular, a theorem whose *hypotheses* include the desired moment estimate is not a proof of that estimate.

See **[PROOF_STATUS.md](PROOF_STATUS.md)** for a theorem-by-theorem inventory of the seven main theorems, the exponential-moment lemma, and the appendix's list-Fano theorem.

## Source files

| Module | Purpose |
| --- | --- |
| `PassK/Values.lean` | Finite distributions; values of pass@k policies with dependent tuple entries |
| `PassK/Definitions.lean` | Optimal value, standard/robust evaluation, demonstrator gap and its nonnegativity |
| `PassK/Coverage.lean` | Weighted coverage, greedy comparison and multiplicative updates |
| `PassK/GreedyCoverage.lean` | Coverage maximization step |
| `PassK/OnlineRegret.lean` | Positive weights, potential invariance, conditional algebraic regret bound |
| `PassK/Bounds.lean` | Signed-regret identities, quantization inequalities |
| `PassK/Preliminaries.lean` | Regret bookkeeping |
| `PassK/PolicyMixture.lean` | Uniform mixture of **whole response tuples** and value/excess averaging |
| `PassK/OneStepIID.lean` | One-round expected regret equals population excess |
| `PassK/FiniteTail.lean` | Finite Markov and union inequalities |
| `PassK/MomentToTail.lean` | Tail implication *assuming* the moment bound |
| `PassK/StandardRobustPAC.lean` | Fixed/robust PAC implications *assuming* moment/reduction bounds |
| `PassK/FiniteTesting.lean` | Two-point testing lower bound via overlap |
| `PassK/TwoPoint.lean` | Elementary two-world impossibility example |
| `PassK/LowerBounds.lean` | Generic minimax reduction *assuming* hard-instance witnesses |
| `PassK/UpperBounds.lean` | Logical relationship between standard and robust success criteria |

The code makes explicit the crucial distinction between a policy producing dependent `Fin k → Y` tuples and a mixture that samples one whole snapshot before drawing a tuple.

## Run locally

The project is configured for **Lean 4.34.1** and a Mathlib revision matching that toolchain.

```sh
lake update
lake exe cache get
lake build
```

In the project's GitHub repository, the included `.github/workflows/lean.yml` will run `lake build` on each push.

### Verification caveat

The code-generation environment had no executable Lean compiler or toolchain download access. The **new modules have not passed a local `lake build`**. Previous user-supplied logs show several older modules compiling; that does not certify the new files. If compilation fails, use the exact file/line diagnostic to revise the corresponding lemma. 

The project does not declare `axiom` or use `sorry` to impersonate completed proofs. Only the statements actually proved in Lean (once compiled) can be called verified, not the unformalized main paper claims.
